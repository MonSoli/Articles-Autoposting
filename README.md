# Автопостинг статей на vc.ru

Система, которая пишет обучающие статьи о классической одежде и публикует их
на vc.ru. Тексты пишет Claude — **на вашей Pro/Max-подписке, без API и без оплаты
за токены**. Публикация — автоматизацией браузера в веб-интерфейсе.

Внутри — база знаний из ресёрча по российским, китайским, европейским и американским
источникам: как устроен алгоритм vc.ru, какие форматы дают вовлечение, о чём писать
и как оформлять.

---

## Как это устроено

```
Банк тем (40 углов из ресёрча)
        │
        ▼
Пайплайн генерации — до 7 обращений к Claude в одной цепочке
        │   1. Угол и конфликт + 5 вариантов заголовка
        │   2. Структура под регламент площадки
        │   3. Черновик
        │   4. Разбор придирчивым редактором
        │   5. Переписывание по замечаниям
        │   6. SEO-доводка по замечаниям анализатора
        │   7. Метаданные, подсайт, теги, факт-чек
        ▼
Обложка 1920×1080 + фотографии из открытых источников
        │
        ▼
Проверка регламента — объём, заголовок, абзацы, штампы ИИ
        │
        ▼
Публикация через Playwright — заголовок, тело, обложка, подсайт, теги
```

### Почему Claude вызывается именно так

Требование было — «пишет Claude, но не по API, а через обычную подписку».

Система использует **Claude Code CLI в headless-режиме** (`claude -p`). Он авторизуется
тем же аккаунтом, что и веб-интерфейс, и расходует лимиты подписки Pro/Max, а не
оплачиваемые токены API. Это полноценный программный доступ к чату без API-ключа.

Эмуляцию кликов в claude.ai я сознательно не делал: это ломается на каждом обновлении
вёрстки, упирается в Cloudflare и прямо запрещено правилами сервиса. Через CLI результат
для вас тот же — текст пишет Claude, платит подписка, — но работает стабильно.

## Установка

```bash
# 1. Зависимости
pip install -r requirements.txt
python -m playwright install chromium

# 2. Claude Code CLI — тем же аккаунтом, что и подписка
npm install -g @anthropic-ai/claude-code
claude                    # разовый вход в свою учётную запись

# 3. Конфиг
cp config.example.yaml config.yaml

# 4. Проверка окружения
python run.py doctor
```

Если в окружении задан `ANTHROPIC_API_KEY`, уберите его — иначе вызовы уйдут в API
и будут тарифицироваться. Система вырезает эту переменную при вызове, но лучше
не держать её вовсе.

## Использование

```bash
# Контент-план: какие темы и в каком порядке
python run.py topics -n 10

# Сгенерировать статью по лучшей неиспользованной теме
python run.py generate

# Или по своей теме
python run.py generate --topic "Почему шерсть Super 150s не для города"

# Пачкой
python run.py batch -n 5

# Посмотреть готовое и проверить
python run.py review a1b2c3d4e5f6

# Разовый вход в vc.ru (сессия сохранится)
python run.py login

# Заполнить редактор, НЕ публикуя — для проверки глазами
python run.py publish a1b2c3d4e5f6

# Опубликовать по-настоящему
python run.py publish a1b2c3d4e5f6 --live

# Что уже сделано
python run.py status
```

### Режим проверки по умолчанию

`publish` без `--live` заполняет редактор и останавливается, не нажимая «Опубликовать».
Вы видите готовый материал в браузере и решаете сами. Это сделано намеренно: статьи
идут от вашего имени в публичную ленту, и первые несколько выпусков стоит посмотреть
руками, прежде чем доверять полный автомат.


### Что дал ресёрч

- **Россия.** Ниша экспертного контента о классике почти пуста: есть либо магазинные
  блоги, либо переводные компиляции без цен и без привязки к тому, что реально
  можно купить здесь. Рублёвые цены и доступность — наше преимущество.
- **Китай** (小红书, 知乎). Работают форматы 避雷 («чего НЕ покупать»), 通勤 (комплекты
  на рабочую неделю), 平替 («достойная замена дешевле») и градация по бюджету.
  Платформы вознаграждают прикладную воспроизводимость — то же даёт сохранения на vc.ru.
- **Европа** (Permanent Style). Формат честного отчёта о своей покупке со сроками
  и разочарованиями даёт максимальный кредит доверия. В рунете почти не встречается.
- **США** (Die Workwear!, Put This On). Историко-технический разбор одного узкого
  вопроса до дна и скепсис к маркетингу — позиция «мы на стороне читателя».

Скрещивание этих четырёх школ и есть содержательная стратегия проекта.

## Публикация: настройка селекторов

Вёрстка vc.ru меняется, поэтому все селекторы вынесены в
`autoposter/publishing/selectors.yaml`. Для каждого элемента задан список кандидатов —
публикатор берёт первый сработавший.

Если что-то перестало находиться:

```bash
python run.py calibrate
```

Команда откроет редактор, покажет все найденные поля ввода и кнопки, сохранит скриншот
и HTML страницы в `data/screenshots/`. По этим данным правится `selectors.yaml` —
без изменения кода.

**Селекторы в репозитории — стартовые значения, собранные по описаниям редактора.**
Проверить их на живой странице из моей среды было нельзя (vc.ru закрыт сетевой политикой),
поэтому первый запуск почти наверняка потребует одной калибровки. Это разовая операция.

### Как переносится форматирование

Основной путь — вставка HTML через буфер обмена: блочный редактор Osnova разбирает
rich-text в свои блоки, и `<h2>`, `<ul>`, `<ol>`, `<blockquote>` становятся настоящими
заголовками, списками и цитатами за одну операцию. Если вставка не срабатывает,
включается запасной путь — посимвольный ввод простым текстом: разметка теряется,
но текст доходит целиком.

Врезки «Цифра», иллюстрации и опросы помечаются в тексте и ставятся отдельными блоками.

## Проверки перед публикацией

`validate()` не даёт опубликовать материал, нарушающий регламент:

- заголовок длиннее 90 знаков (обрежется в ленте);
- нет подзаголовка (он же meta description);
- объём меньше 6 000 знаков (мало шансов на «Популярное») или больше 18 000;
- меньше трёх H2-подзаголовков;
- нет обложки — материал уйдёт в ленту без картинки;
- абзацы длиннее 600 знаков;
- штампы ИИ-текста («в современном мире», «важно отметить» и прочие).

Обойти можно флагом `--force`, но лучше исправить.

## SEO

Отдельный этап пайплайна: анализатор проверяет готовый текст и отдаёт модели
конкретный список замечаний, а не общие требования. Проверяется размещение запроса
в заголовке и первом абзаце, плотность вхождений по словоформам (русский язык
флективный, точных вхождений в тексте почти не бывает), подзаголовки-вопросы
под быстрые ответы, длина ответа после них, длина мета-полей, подписи к иллюстрациям.

**Если после правки оценка падает — правка откатывается.** Текст пишется для людей,
оптимизация вторична.

```bash
python run.py review <id>     # покажет оценку, замечания и таблицу вхождений
python run.py generate --no-seo
```

## Фотографии в статьях

Модель отмечает места под иллюстрации маркером `[ИЛЛЮСТРАЦИЯ]` с описанием на русском.
Описания переводятся в поисковые запросы на английском (той же подпиской Claude —
у стоков на английском несопоставимо больше материала), фотографии ищутся, скачиваются
и вставляются в редактор.

```bash
python run.py photos "wool fabric texture"   # проверить поиск
python run.py illustrate <id>                # подобрать фото к готовой статье
python run.py generate --no-photos
```

### Источники и почему именно они

| Источник | Ключ | Хранение у себя | Роль |
|---|---|---|---|
| **Met Museum** | не нужен | разрешено (CC0) | **основной.** Костюмный институт — крупнейшее открытое собрание костюма. Кураторские метаданные (`objectName`, `classification`, `medium`) дают точность отбора несопоставимо выше пользовательских тегов |
| **Pexels** | бесплатный | разрешено | современные кадры там, где музей бессилен |
| **Wikimedia Commons** | не нужен | разрешено | исторический и справочный слой |
| **Openverse** | опционально | по лицензии | добор через агрегатор. Без токена лимит около сотни запросов в сутки |
| Pixabay | бесплатный | **обязательно** | резерв. Много изображений, сгенерированных нейросетями |
| Unsplash | бесплатный | **запрещено** | **не используется по умолчанию** |

**Про Unsplash.** Его условия требуют показывать изображения только по возвращённым
ссылкам и запрещают раздавать файлы со своей стороны. Мы загружаем файлы в редактор
vc.ru, то есть неизбежно рехостим — это нарушение. Провайдер оставлен в коде помеченным
`allows_download = False` и при скачивании пропускается. Pixabay требует ровно обратного:
хранить у себя и не хотлинкать постоянно. Единой политики не существует, поэтому флаг
задан у каждого источника.

### Отбор без компьютерного зрения

Кандидаты ранжируются по метаданным. Главная ловушка темы — английское `suit`:
без стоп-листа треть выдачи будет скафандрами, гидрокостюмами, спортивными костюмами
и судебными исками. Поэтому попадание стоп-слова дисквалифицирует кандидата,
совпадение точной биграммы запроса весит больше двух отдельных слов, а музейные
источники получают бонус за кураторскую разметку.

### Атрибуция

Собирается автоматически по схеме TASL (название — автор — источник — лицензия)
и попадает в подпись под фотографией. Для CC0 и public domain она не обязательна,
для остальных лицензий ставится всегда. Openverse отдаёт готовую строку — она
используется как есть.

Отдельно про людей на фото: свободная лицензия покрывает авторское право, но **не права
личности**. Ни один сток не гарантирует согласие изображённых людей. Для иллюстрации
статьи это допустимо, для рекламного модуля — нет. Безопаснее кадры без лиц: детали
пиджака, руки портного, фактура ткани, обувь. Материалы с пометками об ограничениях
(права личности, товарные знаки) отсеиваются автоматически.

## Факт-чек — обязательный шаг

Пайплайн отдельно просит модель выписать все утверждения, которые нужно проверить:
цены, сроки, характеристики, названия брендов и магазинов. Список попадает в
`data/articles/<id>.md` и печатается перед публикацией.

**Проверяйте его.** Модель пишет правдоподобные цифры, но не знает сегодняшних цен
в конкретных магазинах. Публикация непроверенных чисел от вашего имени бьёт ровно
по тому активу, ради которого всё делается, — по доверию аудитории.

По той же причине статьи в формате «я купил и носил» стоит писать только про то,
что вы действительно покупали и носили. Выдуманный личный опыт — самый быстрый способ
потерять аудиторию, когда он вскроется в комментариях.

## Структура проекта

```
autoposter/
├── knowledge/            база знаний (правьте под себя)
├── generation/
│   ├── claude_backend.py вызовы Claude через подписку
│   ├── prompts.py        промпты шести этапов
│   └── pipeline.py       сборка статьи
├── publishing/
│   ├── vcru.py           Playwright-драйвер редактора
│   ├── selectors.yaml    селекторы (правятся без кода)
│   └── formatter.py      блоки → HTML + проверки регламента
├── media/cover.py        генератор обложек
├── topics.py             банк из 40 тем
├── models.py             статья, блоки, разбор markdown
├── store.py              SQLite: что сгенерировано и опубликовано
└── cli.py
```

Данные (`data/`) в репозиторий не попадают: там профиль браузера с вашей сессией,
черновики и база состояния.

## Тесты

```bash
python -m pytest tests/ -q
```

Покрыт разбор markdown в блоки, разбор ответов модели, конвертация в HTML,
проверки регламента и планирование тем. Сетевые части (вызов Claude, Playwright)
тестами не покрыты — они проверяются командой `doctor` и режимом проверки.

## Ограничения, о которых стоит знать

1. **Селекторы требуют первичной калибровки** — см. выше.
2. **Лимиты подписки.** Один материал — до 7 обращений к модели, и база знаний
   выросла: промпт этапа черновика — порядка 65 000 знаков. На Pro это ощутимо;
   при упоре в лимит бэкенд ждёт и повторяет. Для потока в несколько статей в день
   имеет смысл Max. Флаги `--fast` (без критики) и `--no-seo` сокращают расход.
3. **Накрутка запрещена площадкой** и в системе не реализована. Рост даёт качество
   материала и ответы на комментарии в первый час — это и есть то, что читает алгоритм.
4. **Полный автопилот — плохая идея на старте.** Первые выпуски проверяйте руками,
   пока не убедитесь в стабильном качестве.
